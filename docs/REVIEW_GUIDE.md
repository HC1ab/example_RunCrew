# 코드 리뷰 가이드

리뷰의 목적은 **결함을 찾는 것**과 **지식을 나누는 것**입니다. 사람이 아니라 코드를 리뷰합니다.

> "Code is read more often than it is written." — Guido van Rossum

## 피드백 태그

모든 리뷰 코멘트는 태그로 시작해 **얼마나 중요한지**를 바로 알 수 있게 합니다.

| 태그 | 의미 | 머지 전 처리 |
|------|------|--------------|
| `[MUST]` | 반드시 고쳐야 함. 버그, 보안 문제, 요구사항 누락, 데이터 손실 위험 | **필수**. 해결 전 머지 금지 |
| `[SHOULD]` | 강하게 권장. 가독성, 유지보수성, 테스트 보강, 더 나은 설계 | 고치거나, 안 고치는 이유를 답글로 남김 |
| `[NITS]` | 사소한 의견. 이름, 공백, 표현 등 취향 차이 | 선택 |
| `[QUESTION]` | 이해를 위한 질문. 의도나 배경 확인 | 답변 필요 |
| `[PRAISE]` | 잘한 점 칭찬 | — |

### 좋은 코멘트의 형태

```
[태그] 무엇이 문제인지 → 왜 문제인지 → 어떻게 하면 좋을지
```

**예시**

```
[MUST] commits가 비어 있으면 median([])이 null을 반환하는데, 아래 toFixed()에서 TypeError가 납니다.
첫 배포가 봇 커밋만 포함한 경우 재현됩니다. round()처럼 null을 먼저 확인해 주세요.
```

```
[SHOULD] 등급 기준값(24, 168, 720)이 함수 안에 숫자로 박혀 있어 의미를 알기 어렵습니다.
HOURS_PER_DAY 같은 상수로 빼면 DORA 기준이 바뀔 때 고치기 쉬울 것 같아요.
```

```
[NITS] dep보다 deployment가 더 읽기 쉬울 것 같습니다.
```

```
[PRAISE] 재시도할 때 최신 main에서 다시 계산하는 방식 좋네요. 충돌 해결 로직이 필요 없어졌어요.
```

## 리뷰어 체크리스트

### 1. 목적
- [ ] PR 설명과 연결된 이슈를 읽고 **왜** 바꾸는지 이해했다
- [ ] 변경이 이슈의 완료 조건을 만족한다

### 2. 정확성
- [ ] 경계 조건(빈 배열, null, 0, 첫 실행)을 처리한다
- [ ] 에러가 나면 원인을 알 수 있는 메시지를 남긴다
- [ ] 동시에 실행되어도 문제가 없다 (워크플로우)

### 3. 보안
- [ ] 토큰, 웹훅 URL 같은 민감정보가 코드나 로그에 남지 않는다
- [ ] 워크플로우 `permissions`가 필요한 만큼만 열려 있다

### 4. 테스트
- [ ] 바뀐 로직에 테스트가 있다
- [ ] CI가 통과했다

### 5. 가독성
- [ ] 이름만 보고 역할을 알 수 있다
- [ ] 주석은 *무엇*이 아니라 **왜**를 설명한다

### 6. 문서
- [ ] README, Wiki, ADR 중 고쳐야 할 문서가 함께 바뀌었다

## 리뷰어 원칙

- **24시간 안에** 첫 응답을 남깁니다. 바로 못 보면 언제 볼지라도 알려 주세요.
- 한 번에 **400줄 이상** 보지 않습니다. 너무 크면 PR을 나눠 달라고 요청합니다.
- 질문은 비난처럼 들리지 않게 씁니다. "왜 이렇게 했어요?" 대신 "이렇게 한 이유가 궁금해요. 혹시 ~ 때문인가요?"
- 대안을 제시할 수 있으면 함께 적습니다. GitHub의 **Suggested change** 기능을 활용합니다.
- 잘한 점도 꼭 하나 이상 남깁니다 (`[PRAISE]`).

## 작성자 원칙

- PR을 올리기 전에 스스로 한 번 리뷰합니다.
- 피드백은 개인에 대한 평가가 아닙니다. 모든 코멘트에 답글이나 반영 커밋으로 응답합니다.
- 반영한 코멘트는 커밋 링크를 남기고 **Resolve conversation** 처리합니다.
- 의견이 다르면 이유를 설명하고, 결론이 나지 않으면 이슈나 Discussion으로 옮깁니다.

## 리뷰 결과 선택

| 선택 | 언제 |
|------|------|
| **Approve** | `[MUST]`가 없고 머지해도 된다고 판단할 때 |
| **Request changes** | `[MUST]`가 하나라도 있을 때 |
| **Comment** | 질문이나 `[SHOULD]` / `[NITS]`만 있을 때, 또는 자기 PR을 셀프 리뷰할 때 |
