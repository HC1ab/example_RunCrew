# ADR-0003: PR은 merge commit 방식으로 머지한다

- **상태**: 승인됨
- **날짜**: 2026-11-14 (실제 결정: 2026-10-15)
- **결정자**: @HC1ab
- **관련**: PR #19, [CONTRIBUTING](../../CONTRIBUTING.md#pull-request)

## 배경

GitHub는 PR 머지 방식으로 merge commit, squash, rebase를 제공합니다. DORA **리드 타임**은 "커밋 작성 시각 → 배포 시각"으로 계산하므로, 머지 방식에 따라 커밋 시각이 보존되는지가 지표 정확도에 직접 영향을 줍니다.

## 검토한 선택지

| 선택지 | 커밋 시각 | 히스토리 | 리드 타임 영향 |
|--------|-----------|----------|----------------|
| A. Squash and merge | **머지 시각으로 바뀜** | 깔끔 (PR당 1커밋) | 리드 타임이 거의 0으로 왜곡 |
| B. Rebase and merge | 원래 작성 시각 유지 | 선형 | 정확, 하지만 PR 경계가 히스토리에서 사라짐 |
| C. **Create a merge commit** | 원래 작성 시각 유지 | PR 단위로 묶여 보임 | 정확 |

## 결정

> **C. merge commit 방식으로 머지한다.**

리드 타임 정확도를 지키면서, 히스토리에서 PR 단위(어떤 커밋들이 한 PR로 들어왔는지)를 볼 수 있기 때문입니다. 대신 PR 안의 커밋을 **Conventional Commits + 하나의 논리적 변경** 단위로 작게 유지해 히스토리를 읽기 쉽게 합니다.

## 결과

- 👍 리드 타임이 실제 작업 시간을 반영 (예: PR #22 배포 리드 타임 8분)
- 👍 `git log --first-parent main`으로 PR 단위 이력 확인 가능
- 👎 히스토리에 머지 커밋이 늘어남 → 커밋 메시지 규칙으로 가독성 보완
- 🔁 브랜치 보호 규칙에서 머지 방식을 merge commit으로 제한하는 것을 검토
